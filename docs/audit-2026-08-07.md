# Argus Repository Audit — 2026-08-07

Seven parallel agents audited security, database, frontend, API design, the ingest pipeline,
tooling/CI, and architecture. Findings below were verified by reading code, running the toolchain,
querying the live Neon database read-only, and calling the live Polymarket APIs.

Scope: 48 TS/TSX files, 4,721 LOC (3,857 excluding `src/components/ui`), 7 migrations, 11 API routes.

---

## Executive Summary

**Argus is a well-built dashboard that is currently switched off, wearing the description of an
alerting system it has never contained.**

Three facts, each independently verified, define the state of this repo:

1. **The pipeline has not run in 103 days.** Newest trade in the database is `2026-04-26`; today is
   `2026-08-07`. There is no cron, no `vercel.json`, no scheduler. `/api/ingest` exports `POST` only
   and sits behind Clerk auth, so it can _only_ be triggered by a human clicking Refresh while
   logged in. Both grouped views cap `timeWindowHours` at 168, so **they return zero groups for
   every user right now.**

2. **The alerting feature — the stated core value proposition — is 0% implemented.** No Telegram
   code, no Discord code, no notification sender of any kind. Nothing has ever written to `alerts`
   or read `alert_channels` (both tables: 0 rows). The Clerk webhook that populates `users` is three
   `// TODO` stubs that `console.log` and return 200, so `users` is empty — which means
   `alerts.user_id NOT NULL REFERENCES users(id)` makes alerting _structurally impossible_ until
   that webhook is implemented.

3. **Two of the three documented whale-detection rules do not exist.** `WHALE_THRESHOLD_NEAR_EXPIRY`,
   `EXPIRY_WINDOW_HOURS_DEFAULT`, and `EXPIRY_WINDOW_HOURS_GEOPOLITICS` have zero call sites. Ingest
   passes only the $250k threshold as an upstream filter, so sub-$250k trades are never even
   fetched — the $15k rules cannot fire on data that was never retrieved. All 589 rows carry
   `is_whale = true` and the hardcoded literal `detection_rule = 'threshold_250k'`; `time_to_expiry_hours`
   is NULL on every row. (One row is $246,912 — below the threshold it claims.)

The gap between `CLAUDE.md`/`README.md` and the shipped product is the single most consequential
finding. The schema, the Zod schemas, and the docs all describe a system roughly one tier more
complete than what exists.

**Security is genuinely good, with one urgent exception.** Zero SQL injection across ~20 query
sites, zero IDOR, no secrets leaked, correct parameterization including the ORDER BY clause. But
the app's _entire_ authorization is `src/proxy.ts` middleware, and both the auth library and the
framework currently ship known middleware-bypass vulnerabilities:

| Package         | Installed | Advisory                                                           | Severity     | Patched        |
| --------------- | --------- | ------------------------------------------------------------------ | ------------ | -------------- |
| `@clerk/nextjs` | 6.36.7    | GHSA-vqx2-fgx2-5wq9 — _Middleware-based route protection bypass_   | **CRITICAL** | ≥6.39.2        |
| `@clerk/nextjs` | 6.36.7    | GHSA-w24r-5266-9c3c — authorization bypass                         | HIGH         | ≥6.39.3        |
| `next`          | 16.1.1    | GHSA-26hh / -267c / -492v / -36qx — _Middleware / Proxy bypass_ ×4 | HIGH         | ≥16.2.5–16.2.6 |

`/api/ingest`, `/api/backfill`, `/api/trades`, `/api/filters`, and `/api/trades/grouped` have no
in-handler `auth()` fallback — a middleware bypass exposes all of them, including the two write
endpoints. `next` is pinned exact (`"next": "16.1.1"`), so `pnpm update` will not move it.

**The code is in better shape than the scaffolding around it.** `tsc --noEmit` passes clean under
`strict: true` with zero `any`, zero `@ts-ignore`, zero `eslint-disable` across 4,721 lines. But
there are **zero tests**, **zero CI**, and `main` currently **fails its own `pnpm lint`** and
`pnpm format:check`. Nothing converts the evident care into a guarantee, which is why the lint
failure and 78 dependency advisories accumulated unnoticed.

**Roughly a third of the codebase is deletable with no functional loss** — `following/page.tsx` is an
80% verbatim fork of `page.tsx`, and the two grouped-trade routes are 92% identical including 81
lines of duplicated business logic.

## 1. What We're Doing Well

These are not consolation prizes. Several are things most codebases at this stage get wrong.

### Security fundamentals are genuinely strong

- **Zero SQL injection.** All ~20 `sql` call sites use Neon tagged templates with real bind
  parameters. No `sql.unsafe`, no `sql.query`, no raw `Pool`/`Client`, no string-concatenated SQL
  fragments anywhere in `src/`.
- **Sorting is parameterized, not interpolated.** `src/app/api/trades/route.ts:57-63` uses
  `CASE WHEN ${orderByTime} AND ${orderAsc} THEN ...` with bound booleans instead of splicing an
  ORDER BY string. This is the single most common injection sink in this class of app, and it is
  done correctly — rarely true. It also does _not_ defeat the indexes: verified via
  `PREPARE`/`EXPLAIN EXECUTE` past the generic-plan threshold, the planner constant-folds the CASE
  and uses `idx_trades_timestamp` / `idx_trades_usdc_value` as intended.
- **Zero IDOR.** Every user-scoped query filters on `clerk_id = ${userId}` from the server-side
  `auth()` call, never from client input. Mutations key on `(clerk_id, wallet_address)` rather than
  a row UUID, so there is no object identifier to tamper with.
- **`sanitizeForLike` is correct and universally applied** — escapes `%`, `_`, `\` with Postgres'
  default escape character, called at all four LIKE sites.
- **No secrets exposure.** `.env` untracked, `.gitignore` covers `.env*`, `git log --all --diff-filter=A`
  shows no secret file was ever committed. The only `NEXT_PUBLIC_` value is the Clerk publishable key.
- **No SSRF, no mass assignment, no XSS sink.** The only user-influenced fetch `encodeURIComponent`s
  a path segment against a constant base URL. Zod strips unknown keys. No `dangerouslySetInnerHTML`.
- **Auth enforcement verified end-to-end**, not merely inferred from config: every protected route
  returned 307-to-sign-in unauthenticated; only `/api/health` returned 200.

### The schema is well-modeled

- **Money is `DECIMAL`, never float** — `usdc_value DECIMAL(20,6)`, `size DECIMAL(30,10)`,
  `price DECIMAL(10,8)`. The most common schema mistake in trading apps, simply absent here.
- **Every timestamp is `TIMESTAMP WITH TIME ZONE`.** No naive-timestamp bugs, no timezone drift.
- **`ON DELETE` semantics are deliberate per relationship** — `SET NULL` for `trades.market_id` (a
  trade outlives its market), `CASCADE` for `alerts`/`alert_channels` (children of a user).
- **Down migrations are correct and reversible.** Each drops the table before its ENUM; db-migrate
  reverses order so FKs resolve without `CASCADE`. No schema drift — every column referenced in code
  exists in migrations, and the live DB matches what's checked in.
- **`followed_wallets` upsert is fully correct under concurrency** —
  `ON CONFLICT (clerk_id, wallet_address)` backed by a real UNIQUE constraint, with
  `COALESCE(EXCLUDED.label, ...)` so a re-follow doesn't clobber a label.
- **Hex address casing is handled.** Live data is 100% lowercase in both tables — the classic
  checksummed-address bug is avoided (in app code rather than by CHECK constraint, but avoided).

### Input validation is disciplined

`safeParse` everywhere, never `parse`. All six input-taking routes validate, return 400, and include
`details`. Path params are validated too — the step most codebases skip. Max lengths, numeric ranges,
and `.default()` on optionals are set consistently. The `nullToUndefined` preprocess is the correct
fix for the real `searchParams.get() → null` problem and is centralized rather than copy-pasted.
Error bodies are consistently `{error: string}` across all 11 routes — the uniform shape is the
harder half to retrofit, and it is already right.

### `src/lib/polymarket.ts` is a properly-built external adapter

Explicit retryable-status set including 429, exponential backoff, `AbortSignal.timeout`, and
`safeParse` on every upstream response with a typed failure path. `passthrough()` on the market
schema is the right call for an API you don't control. Polymarket changing a field shape produces a
logged parse error, not corrupt rows. Blast radius of an upstream change is 2 files — you already
have the adapter, no further abstraction needed.

### Frontend primitives are well-chosen

- **Query-key hygiene is correct.** Every hook puts its full input set in the key and TanStack hashes
  structurally — no cache collisions between filter combinations, and filter changes cannot race.
  That was the bug class expected here and it is not present.
- **`useTradesFilters` uses `useSyncExternalStore` with a real `getServerSnapshot`** — the correct
  SSR-safe primitive for localStorage-backed state, not the usual `useEffect`-and-hope hydration hack.
- **URL is the source of truth for sort/category/event**, with defaults elided from the querystring.
- **`hasMore` via `LIMIT n+1`** is the right technique — cheaper and race-free versus `COUNT(*)`.
- **Dark-theme contrast passes AA**: `muted-foreground` on `card` ≈ 6.7:1, `yellow-500` ≈ 7.5:1,
  `green-400` on `bg-muted/60` ≈ 8.9:1.
- **Stable list keys everywhere** (`trade.id`, `group.id`, `event.conditionId`) — no index keys.
- **Empty states are specific and well-crafted**, including an illustrated CTA on `/following`.

### Type discipline

`strict: true` on, `tsc --noEmit` passes with **zero output**. Zero `any`, zero `@ts-ignore`, zero
`eslint-disable` across the whole codebase. On 4,700 lines with no test pressure, that is not automatic.

### `docs/disco.md` is legitimately good research

Rate-limit tables, the WebSocket 20-minute freeze gotcha, the double-counting `OrderFilled` caveat.
The most valuable file in the repo. Commit `51a20c7` also documents _why_ the gamma API was wrong —
better provenance than most repos keep.

## 2. What We're Doing Poorly

### 2.1 The product doesn't run, and the docs claim it does

| Claim in docs             | Reality                                                                                   |
| ------------------------- | ----------------------------------------------------------------------------------------- |
| "sends real-time alerts"  | Zero notification code exists. `alerts` table: 0 rows, never written.                     |
| "$15k+ near expiry" rule  | Constant defined, zero call sites. Sub-$250k trades never fetched.                        |
| "$15k+ geopolitics" rule  | Same. Also: no "Geopolitics" tag exists in Polymarket's vocabulary.                       |
| "Five main tables"        | Six tables. `followed_wallets` omitted from `CLAUDE.md`.                                  |
| "Public routes: `/`, ..." | `src/proxy.ts:3` does **not** include `/`. The landing page requires auth.                |
| `src/middleware.ts`       | File is `src/proxy.ts` (correct for Next 16). Doc is stale.                               |
| `README.md`               | 100% stock create-next-app boilerplate. Never mentions Argus, Polymarket, Neon, or Clerk. |

`CLAUDE.md` is the primary context file for agents working in this repo and it is **actively
misleading about the auth boundary**. `.env.example` compounds it: the entire NOTIFICATION SERVICES
block is aspirational, and `NEXT_PUBLIC_CLERK_AFTER_SIGN_IN_URL=/dashboard` points at a route that
does not exist — a new dev fills in a Telegram token expecting alerts, gets nothing, then gets 404'd
after signing in.

Onboarding from docs alone is **broken**: `pnpm dev` on a fresh clone crashes at `src/lib/db.ts:4`
with no hint that a Neon URL and Clerk keys are required.

### 2.2 No safety net at all

- **Zero tests.** Definitively verified: no test files, no runner, no config, no `__tests__`
  directories. On an app doing money math, threshold logic, cursor pagination, and SQL filtering.
- **Zero CI.** No `.github/`, no hooks, no lint-staged. Nothing runs on push or PR.
- **`main` is red right now** — `pnpm lint` exits 1 with three `react-hooks/purity` errors
  (`Math.random()` during render, `src/components/WhaleSplash.tsx:56-58`) and `pnpm format:check`
  exits 1 on 18 files. It has been red since commit `56599dc`, undetected.
- Note the specific trap: **Next 16 removed ESLint-during-build**, so broken lint is never caught
  anywhere. Broken TypeScript _is_ caught by `next build` — but at deploy time, not PR time.
- **78 dependency advisories** (2 critical, 44 high) accumulated with no Dependabot/Renovate.
- **No error tracking, no logger, no rate limiting.** Production failures surface only as
  `console.error` into a log tail with no alerting. `/api/health` returns a static `{status:'ok'}`
  without touching the DB — it cannot tell you ingestion has been dead for 103 days. _It didn't._

### 2.3 Shipped by copy-paste instead of parameterization

Measured with `diff`:

| Pair                                           | Sizes     | Shared  | %       |
| ---------------------------------------------- | --------- | ------- | ------- |
| `trades/grouped` vs `trades/following/grouped` | 250 / 248 | **231** | **92%** |
| `page.tsx` vs `following/page.tsx`             | 564 / 453 | **363** | **80%** |
| `trades` vs `trades/following`                 | 75 / 76   | **58**  | **77%** |

The duplicated grouped-route code includes `RawTrade`, `classifyGroupType`, `generateGroupId`, and
`buildTradeGroup` — **81 lines of the actual product logic**, living in two places. The only genuine
deltas across each pair are an `auth()` guard and one `INNER JOIN`.

Six formatting helpers are reimplemented 2–4× across four files. **They have already diverged**:
`formatPrice` uses `maximumFractionDigits: 2` in the pages and `4` in `GroupedTradesView.tsx:104`,
so prices render differently in the two views today. `formatWallet` gained a `label` param in
`following/page.tsx:48` but not in `page.tsx:50`. `page.tsx` has infinite scroll; `following` silently
caps at 10 rows and the UI apologizes for it ("limited on mobile") because there is no way to page.

### 2.4 A type lie the compiler cannot catch

`src/hooks/useTrades.ts:14-16` declares `size`/`price`/`usdc_value` as `number`. They are `DECIMAL`
columns and the Neon driver returns NUMERIC as **strings** — confirmed against the live DB:
`usdc_value → "246912.137472"`.

The codebase contradicts itself: `src/app/api/trades/grouped/route.ts:21-23` types the same three
columns as `string` and `parseFloat`s them. Both declarations cannot be right. So `/api/trades` and
`/api/trades/grouped` return the same fields with different JSON types.

It survives today purely by coercion luck — `Intl.NumberFormat.format` accepts decimal strings and
`"250000" >= 1000000` coerces numerically. It breaks silently the moment anyone writes
`a.usdc_value + b.usdc_value` (string concatenation, **no type error**) or `.toFixed()` (runtime
throw). `src/app/page.tsx:200` already stuffs a string into `useState(0)`.

Root cause: **no runtime validation on any API response.** Zod is used for request input only; every
fetcher does `return res.json()` blindly cast to an interface.

### 2.5 Pagination is not correct

`ORDER BY t.trade_timestamp` / `usdc_value` with **no unique tiebreaker**. Measured in live data: 17
distinct `usdc_value` values are shared by 46 rows. Postgres does not guarantee stable ordering among
ties across separate `LIMIT/OFFSET` executions, so mobile infinite scroll can render the same trade
twice (React duplicate-key warning) while never rendering its tied sibling. Independently, any ingest
between page fetches shifts every row right by N.

`offset` also caps at 10,000 in the schema while `getNextPageParam` advances unconditionally — at
offset 10,020 the user gets a **400 error state instead of an end-of-list**.

### 2.6 Work is done in the wrong place, at the wrong scale

- **Grouped endpoints have no SQL `LIMIT` — and no SQL `GROUP BY` either.** All grouping happens in
  JavaScript (`grouped/route.ts:192-222`) after pulling raw rows; the validated `limit` is applied in
  JS _after_ that, at `:233`. So `limit` has **zero effect on the database**.
  `?limit=1&timeWindowHours=168` still pulls every whale trade from the last week — every column,
  including TEXT — over the HTTP driver. The JS grouping logic itself is correct (verified: the
  colon-split key is safe, no trade lands in two groups, and the JS day-bucket agrees with
  `date_trunc` because the Neon session TZ is UTC). It's in the wrong place, not wrong.
- **Every page load fires three trade queries; two are always discarded.** No `enabled` gates. A
  desktop user pays for the mobile infinite query _and_ the grouped query. Every visitor triples DB load.
- **Dragging the amount slider fires a request storm.** Radix `onValueChange` fires per step; each
  step rewrites localStorage → synthetic storage event → all three query keys change → all three
  refetch. One drag across the 10k–1M range at step 10k ≈ **300 requests**.
- **Ingest is one HTTP round-trip per row** — 100 new trades = 100 sequential Neon round-trips,
  before up to 80 more sequential external market fetches in the same request, with no `maxDuration`.
- **`/api/backfill` cannot complete and cannot resume.** Unbounded `SELECT`, serial loop with a 100ms
  sleep, no cursor. At 359 markets that is ≥36s of sleep alone. It restarts from row 1 every time, so
  rows past the timeout boundary are **permanently un-backfilled**.
- **The followed-wallet join is unindexable.** `ON LOWER(t.proxy_wallet) = fw.wallet_address` defeats
  `idx_trades_proxy_wallet`, which has **0 scans since table creation**. EXPLAIN confirms a seq scan
  plus full sort on every `/following` request. All stored values are already lowercase — the
  `LOWER()` buys nothing.

### 2.7 Silent failures everywhere

- **Follow/unfollow errors are completely invisible.** No `onError` on any of the three mutations,
  and `FollowWalletButton` never reads `mutation.error`. On a 401 the star flickers and reverts with
  zero feedback.
- **Refresh errors are console-only** — indistinguishable from "no new trades."
- **The Clerk webhook verifies the signature, does nothing, and returns 200.** Clerk marks the event
  delivered and never retries. This is the worst kind of swallow.
- **`/api/ingest` reports `backfilled` as attempts, not successes.** When Polymarket is fully down it
  returns `200 {backfilled: 50}` having backfilled zero.
- **PATCH with an absent `label` wipes the label** — `{}` parses fine, `label` is `undefined`, and
  `SET label = ${label || null}` writes NULL. PATCH means merge; absent ≠ null.
- **Malformed JSON returns 500 instead of 400**, so retry logic retries a request that can never succeed.

### 2.8 Accessibility gaps

No `htmlFor` on any form label — the Select trigger, search input, slider, and time-window select all
have **no accessible name**. Sortable `<th>`s are `onClick`-only: no `tabIndex`, no `onKeyDown`, no
`aria-sort` — keyboard users cannot sort at all. No `prefers-reduced-motion` handling anywhere, while
a full-viewport whale animation translates and rotates across the screen. `WhaleSplash` sets
`pointerEvents: 'auto'` over `inset-0 z-50`, **swallowing every click on the page for ~4.3 seconds**
with no keyboard dismissal. `<Link>` wrapping `<Button>` produces invalid nested-interactive HTML.

## 3. What We Can Improve — Prioritized

Ordered by value per unit of effort. Steps 0–2 are prerequisites: they make everything after them
self-reporting and stop fixes from having to be written four times.

### Phase 0 — Stop the bleeding (half a day)

1. **Patch the middleware-bypass advisories.**
   `pnpm up @clerk/nextjs@^6.39.3 next@^16.3.0 eslint-config-next@^16.3.0`.
   Un-pin `next` from exact. Then add in-handler `auth()` checks to `/api/ingest`, `/api/backfill`,
   `/api/trades`, `/api/filters`, `/api/trades/grouped` so middleware stops being a single point of
   failure. The four user-scoped routes already do this — extend the pattern.
2. **Gate `/api/backfill` on a `CRON_SECRET` bearer token** with a timing-safe compare (length check
   first — `timingSafeEqual` throws on mismatch), not on "any signed-up user."
3. **Get `main` green.** `pnpm format` once as a single mechanical commit; hoist the `WhaleSplash`
   randomness into `useState(() => ...)`. Add `pnpm-lock.yaml` and `next-env.d.ts` to `.prettierignore`
   first, or `pnpm format` will rewrite the 201KB lockfile.
4. **Add CI** — `.github/workflows/ci.yml` running `pnpm install --frozen-lockfile`, `pnpm lint`,
   `pnpm exec tsc --noEmit`, `pnpm format:check` on PR and push to main; make it a required check.
   Add a `"typecheck": "tsc --noEmit"` script. Add Dependabot.

### Phase 1 — Decide what the product is (product call, not engineering)

The schema, the Zod schemas, and the docs describe an alerting system. The code is a dashboard.
**Pick one.** Both are legitimate; the half-built middle is the worst option because it misleads every
future contributor and every agent reading `CLAUDE.md`.

- **If dashboard:** delete `src/schemas/alert.ts`, `src/schemas/channel.ts`, `src/schemas/market.ts`,
  the `alerts`/`alert_channels` migrations, the three dead threshold constants, and every alerting
  claim in `CLAUDE.md`/`.env.example`. Rewrite `README.md`.
- **If alerting:** implement the Clerk webhook upserts _first_ (nothing else can work until `users`
  has rows), then `src/lib/notify.ts` with per-channel senders and an `alerts` row per (trade, channel).

Either way: **fix `CLAUDE.md` today.** It is wrong about the auth boundary, the middleware filename,
the table count, and the detection rules.

### Phase 2 — Make ingestion actually run

5. **Add a `GET` handler to `/api/ingest`** guarded by `CRON_SECRET` (Vercel Cron issues GET, so a
   cron entry alone would 405 — and middleware would reject it first). Add `/api/ingest` to the public
   matcher. Add `vercel.json` with a `crons` entry and `export const maxDuration`.
6. **Before scheduling it, add `ON CONFLICT (transaction_hash) DO NOTHING`** and wrap each insert in
   try/catch. Scheduling is exactly what turns the current read-then-insert TOCTOU from "two users
   racing" into "every scheduled run racing a manual refresh" — which today returns a 500 with rows
   half-committed and both backfill blocks skipped.
7. **Fix the retry loop's dead guard** — `src/lib/polymarket.ts:37-45` throws the non-retryable error
   _inside_ the `try`, so its own `catch` swallows it and retries anyway. Every 404 (common for new or
   resolved markets) costs 3 attempts plus backoff, up to 48s per market.
8. **Verify the threshold locally** instead of trusting the upstream filter. This repo already got
   burned by this class of bug once (`51a20c7`: "the gamma API ignores condition_id params"). One
   stored row is already $246,912 while labeled `threshold_250k`.
9. **Add a watermark** and page backwards to it. Currently harmless — 100 trades ≥$250k span ~27 days —
   but at $15k, 500 trades span 25 hours, so `limit=100` becomes a ~5-hour window and any longer gap
   silently drops trades.
10. **Make `/api/health` mean something** — have it fail when `max(trade_timestamp)` is older than the
    expected interval. Add an `ingest_runs` table. Add Sentry (~30 min). _This is the finding that
    would have caught the 103-day outage._

### Phase 3 — Deduplicate before fixing bugs

Do this **before** the correctness fixes in Phase 4, or each one gets written two-to-four times.

11. `src/lib/format.ts` — six helpers, one `POLYGONSCAN_TX` builder. Pick one `formatPrice`
    precision. **−120 LOC, fixes a live inconsistency.**
12. `src/lib/grouping.ts` (`RawTrade`, `classifyGroupType`, `generateGroupId`, `buildTradeGroup`) and
    `src/lib/queries/trades.ts` (one query builder taking a `scope: {kind:'all'} | {kind:'following', clerkId}`).
    **−231 LOC.** This also drops Neon's blast radius from 8 files to 2 and gives one place to
    coerce DECIMAL→number.
13. `<TradesPage scope="all" | "following">` — `following/page.tsx` becomes one line. **−390 LOC.**
14. Delete the proven-dead code: `schemas/alert|channel|market`, `ui/dropdown-menu|dialog|label` (and
    their three Radix deps), `date-fns`, `useIsWalletFollowed`, `useUpdateWalletLabel`, five dead
    constants, `public/*.svg`, and the `/api/filters` `events` query (a `DISTINCT` over a full join,
    computed on every page load, that **no component reads**).

**Total: ~31–35% of the codebase comes out with zero functional loss.** Getting to 40% would mean
cutting the grouped-by-wallet view, which is a real feature — don't.

> On layering: at 3.8k LOC you do **not** need a repository pattern, a service layer, or DTO mapping.
> You need `src/lib/queries/trades.ts` and `src/lib/grouping.ts`. That's it. Anything more is
> over-abstraction at this size.

### Phase 4 — Correctness (now one-line fixes each)

15. **Add `, t.id DESC` to every ORDER BY**, or move to keyset pagination
    (`WHERE (trade_timestamp, id) < ($ts, $id)`), which also removes the 10k offset cliff and the
    deep-scan cost.
16. **Coerce DECIMAL at the query boundary** — one `toTrade()` mapper — and parse API responses with
    Zod in the fetchers so the type and the runtime agree.
17. **Push `LIMIT` into the grouped queries.** Minimum viable: bound the raw fetch and report
    truncation in `meta`. Also fix `meta.totalGroups`, which is computed _after_ `slice(0, limit)` and
    so can never exceed the limit.
18. **Lowercase `wallet` in `tradesQuerySchema`** (as `followWalletSchema` already does) and
    `LOWER()` the comparison — or better, normalize `proxy_wallet` at ingest and add a CHECK
    constraint, then drop the expression entirely.
19. **Reconcile category display vs. filter.** `m.tags->>0 as category` displays the first tag while
    `m.tags ? ${category}` matches any — filter by `NBA`, get rows labeled `Sports`. Also,
    `/api/filters` emits tags that `tradesQuerySchema`'s regex **rejects with a 400** (`"U.S. Politics"`
    fails). Derive both from one source. Given the values are bind parameters, the regex buys nothing.
20. **Add the missing indexes; drop the useless ones.**
    ```sql
    CREATE INDEX idx_trades_wallet_lower_ts ON trades (LOWER(proxy_wallet), trade_timestamp DESC);
    DROP INDEX idx_trades_tx_hash, idx_markets_condition_id, idx_users_clerk_id,
                idx_trades_title, idx_trades_whale;  -- redundant with UNIQUE, or index a constant
    ```
21. **`markets.updated_at` never advances** — 359/359 rows have `updated_at = created_at` while 245
    have a newer `last_synced_at`. Add it to the `DO UPDATE SET` list or install a trigger.

### Phase 5 — Frontend

22. **Gate the three queries with `enabled`** and **move the slider to `onValueCommit`.** Together,

23. **Add `onError` + optimistic updates** to the follow mutations; add `app/error.tsx`; surface the
    refresh error; add a `UserButton` (there is currently **no sign-out affordance anywhere**).

## Appendix — Checked and Found Fine

Recorded so nobody re-flags them:

- **`ORDER BY CASE WHEN $1 ...` does not defeat the indexes.** Neon's HTTP driver sends unnamed
  extended-protocol statements, so the planner has parameter values at Bind time and constant-folds
  the CASE. Verified past the custom→generic plan threshold. Ugly, correct, fast. Leave it.
- **Multiple fills per transaction hash** — sampled 500 live data-api rows twice at different
  thresholds: zero hashes appear more than once. `transaction_hash UNIQUE` holds for this feed.
  Unconfirmed hypothesis, not a finding. If Polymarket changes fill granularity, the natural key
  should become `(transaction_hash, asset_id, proxy_wallet, side)`.
- **`m.tags ? ${category}`** — the literal `?` does not collide with Neon's `$n` placeholders. The GIN
  index is used (267 scans).

- **`.env` is untracked.** Flagged only because it is the thing most likely to be wrong, and isn't.
- **All migrations applied; no schema drift.** Commit `c0cb8df`'s "use market's category field" resolved
